# Blog Fix Skill

## 🎯 任務目標
自動掃描、識別並修正 Hugo 部落格文章目錄（`content/posts/`）中的舊有語法、HTML 標籤、格式錯誤，以及 **Front Matter（標頭檔）的語法問題**，將其標準化為符合 Hugo 規範的 Markdown 格式。

## 🚫 核心鐵律（CRITICAL RULES）
執行任何操作前，必須絕對遵守以下原則：
1. **嚴禁修改原始程式碼內容**：針對代碼區塊，**只能**在外層加上 ` ``` ` 標記。絕對不可修改變數名稱、縮排、括號或任何代碼邏輯。
2. **強制 Diff 確認機制**：每次修改單篇文章後，**必須**先顯示 `git diff`（或修改前後對比），並暫停執行，等待使用者回覆「同意」後，才能寫入檔案或進行 Commit。
3. **避免破壞性全域替換**：嚴禁盲目使用 `replaceAll`，必須逐次/逐行確認替換範圍，避免殘留字元（如 `%}`）。

## 🔍 問題識別與轉換規則

在掃描文章時，請依據以下規則進行轉換：

### 1. Front Matter (標頭檔) 檢查
確保文章頂部的 YAML 區塊符合 Hugo 規範：
- **閉合檢查**：必須以 `---` 開頭，並以 `---` 結尾。
- **冒號格式**：YAML 屬性的冒號後必須有空格（例：`title:My Post` ➔ `title: My Post`）。
- **特殊字元引號**：若標題或描述包含冒號、引號等特殊字元，必須用雙引號包裹（例：`title: "My Post: Part 1"`）。

### 2. 圖片語法轉換
- **舊語法**：`{% img /images/posts/NAME.png %}`
- **新語法**：`![NAME](/images/posts/NAME.png)`
- ⚠️ **前置檢查**：替換前，需透過終端機檢查對應的圖片實體檔案是否存在。

### 3. HTML 轉 Markdown
將所有殘留的 HTML 標籤轉換為標準 Markdown：
- `<h1>` 到 `<h6>` ➔ `#` 到 `######`
- `<pre><code>...</code></pre>` ➔ ` ```語言 ... ``` `
- `<a href="url">text</a>` ➔ `[text](url)`
- `<strong>` 或 `<b>` ➔ `**text**`
- `<em>` 或 `<i>` ➔ `*text*`
- `<ul><li>...</li></ul>` ➔ `- ...`
- `<ol><li>...</li></ol>` ➔ `1. ...`

### 4. 代碼格式修正
- **未包裹的代碼**：找出以 4 個以上空格縮排且未被 ` ``` ` 包裹的文字區塊，判斷為代碼並加上 ` ``` ` 包裹（維持原本縮排不變）。

## ⚙️ 執行流程 (SOP)

### Step 1: 快速掃描
使用以下指令快速找出「可能」存在問題的檔案：
```bash
# 找出舊圖片語法
rg -l '\{% img' content/posts/ -g '*.md'

# 找出可能未包裹的代碼（4+ 空格縮進）
rg -n '^\s{4,}[a-zA-Z]' content/posts/ -g '*.md'
```
*(備註：Front Matter 問題通常在解析單篇文章時一併檢查最為準確)*

### Step 2: 仔細分析與逐檔修復（核心迴圈）
快速掃描的結果僅供參考，**每次只選擇一篇文章**，並嚴格執行以下操作：
1. 讀取文章內容。
2. **仔細分析確認（非常重要）**：針對 Step 1 掃描出的疑點，必須結合上下文仔細分析。確認該語法是否確實為需要修正的錯誤（例如：若舊語法 `{% img %}` 寫在代碼範例區塊內作為教學說明，則不應替換）。
3. 檢查並修復 **Front Matter** 語法錯誤（缺失 `---`、缺空白等）。
4. 確認問題屬實後，根據【問題識別與轉換規則】進行內文標籤與格式替換。
5. 若涉及圖片，執行 `ls -la path/to/image` 確認圖片存在。
6. **輸出 Diff 並暫停**，詢問使用者：「是否同意套用此修改？」。
7. 獲得同意後，儲存檔案。

### Step 3: 本地建構與驗證
修改完成後，執行驗證確保未破壞網站：
```bash
# 1. 執行建構測試 (同時會檢查 Front Matter 是否合法)
hugo

# 2. 檢查靜態輸出（將 SLUG 替換為實際文章目錄）
grep -o '<img[^>]*' public/posts/SLUG/index.html
grep -E '<h[1-6]' public/posts/SLUG/index.html
grep -E '<pre|<code' public/posts/SLUG/index.html
```

### Step 4: 啟動預覽與完整網址測試
確保產生完整的本地預覽網址（例如 `http://localhost:1313/posts/SLUG/`），以便直接點擊或測試：
```bash
# 啟動服務
hugo server -D

# 透過完整網址檢查該篇文章的服務狀態 HTTP Code 是否為 200
curl -s -o /dev/null -w "%{http_code}" http://localhost:1313/posts/SLUG/
```
